# Stealth Typer

**Человекоподобный посимвольный ввод текста в браузере Microsoft Edge.**
Скрипт открывает страницу (или подключается к уже открытому окну), ставит курсор в нужный редактор и
«печатает» ваш текст настоящими нажатиями клавиш — с переменной скоростью, усталостью, паузами и
исправляемыми опечатками. Особенно хорошо работает с **Monaco** (редактор из VS Code), но умеет и обычные
поля: `textarea`, `input`, `contenteditable`.

Главное отличие от `fill()` / вставки из буфера: на странице не появляется «одно большое вставленное значение».
Сайт видит поток отдельных клавиатурных событий: `keydown → input → keyup` на каждый символ.

## 1. Что умеет

- ⌨️ **Настоящие нажатия клавиш** через протокол отладки Chrome (CDP): Shift нажимается отдельным событием,
  у каждой клавиши есть время удержания, события «доверенные» (`isTrusted = true`).
- 🧠 **Скорость не постоянная.** Она плавно меняется между `WPM_MIN` и `WPM_MAX`, зависит от «усталости»
  (чем дольше печатаете, тем медленнее), иногда случаются «разгоны» и «просадки».
- ✍️ **Опечатки и их исправление**: соседние клавиши, перестановка двух букв, двойное нажатие; ошибка замечается
  через 0–3 знака, после чего человек стирает её Backspace и печатает верно. Итог всегда без ошибок.
- ⏸ **Паузы «как у человека»**: на словах, знаках препинания, концах строк, редкие «задумался» и «отдохнул».
- 🧩 **Редактор Monaco**: находит нужный редактор среди нескольких и **работает вместе с его «помощью»**, как человек:
  печатает внутри автозакрытых кавычек, скобок и тегов и перепрыгивает через закрывающие знаки, принимает автоотступ после Enter и подгоняет его
  под ваш текст, не нажимает лишний Enter там, где редактор уже создал пустую строку между тегами.
- 🔤 **Любой текст**: кириллица, `ё`, `—`, `«»`, `№`, эмодзи, табуляция. **Все отступы сохраняются.**
- 🎯 **Два способа поставить курсор**: скрипт ставит сам (редактор, строка, колонка) или вы кликаете мышкой,
  а скрипт печатает с этого места.
- 🪟 **Два режима браузера**: открыть **новое** окно Edge или подключиться к **уже открытому**.
- ✅ **Проверка результата**: после ввода скрипт сверяет текст в поле с исходным и показывает, где расхождение.
- 🗂 **Профили сайтов**: для разных сайтов — свои настройки в одном файле, выбор одной командой.
- 🧪 **Режим `--dry-run`**: проверка логики и оценка времени без браузера.
- 📝 **Лог и скриншот ошибки** — для разбора проблем.

## 4. Установка по шагам (Windows)

### Шаг 1. Установите Python

1. Откройте <https://www.python.org/downloads/> и скачайте последнюю версию Python 3.
2. Запустите установщик.
3. **ОБЯЗАТЕЛЬНО** поставьте галочку **«Add python.exe to PATH»** внизу первого окна установщика.
   Без неё команда `python` потом не заработает — это самая частая ошибка.
4. Нажмите **Install Now** и дождитесь конца установки.

### Шаг 2. Проверьте, что Python установлен

1. Нажмите клавиши **Win + R**, введите `cmd`, нажмите Enter — откроется чёрное окно (командная строка).
2. Введите команду и нажмите Enter:
   ```
   python --version
   ```
3. Должно появиться что-то вроде `Python 3.12.4`. Версия должна быть **3.10 или выше**.
4. Если вместо этого ошибка «python не является внутренней или внешней командой» — попробуйте `py --version`.
   Если и она не работает — переустановите Python и не забудьте галочку из шага 1.
   (Если работает `py`, во всех командах ниже заменяйте `python` на `py`, а `run.bat` откройте в блокноте и сделайте то же.)

### Шаг 3. Скачайте проект

Вариант А — без Git (проще всего):
1. На странице репозитория нажмите зелёную кнопку **Code → Download ZIP**.
2. Распакуйте архив в удобную папку, например `C:\Tools\Stealth_Typer`.
   Путь лучше без лишних сложностей; русские буквы в пути допустимы, но если что-то не работает — переложите в `C:\Tools`.

Вариант Б — через Git:
```
git clone https://github.com/aIeami/stealth-typer.git
cd stealth-typer
```

### Шаг 4. Откройте командную строку в папке проекта

Самый простой способ:
1. Откройте папку проекта в Проводнике (там, где лежит `run.bat`).
2. Щёлкните мышкой в **адресную строку** Проводника (где написан путь к папке).
3. Сотрите путь, напишите `cmd` и нажмите Enter.
4. Откроется командная строка уже в нужной папке.

### Шаг 5. Установите библиотеку

В открытой командной строке выполните:
```
pip install patchright
```
Дождитесь сообщения `Successfully installed ...`. Это делается **один раз**.

> Если `pip` не найден, используйте `python -m pip install patchright`.

### Шаг 6. Проверьте, что всё работает

```
python app/stealth_typer.py --dry-run
```
Скрипт без браузера «напечатает» текст из `texts/input_text.txt` на встроенном симуляторе и покажет итог:
```
[dry-run] знаков: 259, ожидаемое время: 1 мин 6 с
[dry-run] скорость: от 53 до 69, в среднем 62 WPM
[dry-run] опечаток исправлено: 3, лишнего удалено у редактора: 61
[dry-run] результат на симуляторе совпал с исходным текстом
```
Если вы это видите — установка прошла успешно.

> **Если редактируете `.bat`-файлы:** держите их **только на латинице** (без русских букв и комментариев на русском).
> `cmd.exe` не умеет надёжно читать кириллицу в UTF-8 и начинает выполнять обрывки текста как команды
> (`'ебугging-port' не является внутренней или внешней командой`). Сохраняйте в Блокноте с кодировкой ANSI, а лучше просто не добавляйте кириллицу.

### Если вы используете виртуальное окружение (venv)

Виртуальное окружение — необязательно, но если оно у вас есть, `run.bat` его подхватит **сам**: он ищет папку
`venv`, `.venv`, `stealth-env` или `env` рядом со скриптом и запускает Python из неё. Ничего дописывать в `run.bat` не нужно.

Создать окружение (один раз), в папке проекта:
```
python -m venv venv
venv\Scripts\activate
pip install patchright
```
Если окружение называется иначе или лежит в другом месте — откройте `run.bat` в Блокноте и добавьте своё имя папки
в строку `for %%D in (venv .venv stealth-env env) do (`.

Запускать вручную из командной строки, а не через `run.bat`:
```
venv\Scripts\activate
python app/stealth_typer.py
```

> Если вы пишете свой `.bat`, команда активации **обязательно** должна начинаться со слова `call`:
> `call venv\Scripts\activate.bat`. Без `call` управление передаётся файлу активации и **не возвращается** — остальные
> строки не выполняются, а окно сразу закрывается.

## 5. Быстрый старт за 5 минут

Самый простой сценарий: новое окно Edge, вы сами открываете страницу и кликаете в редактор.

1. Откройте `texts/input_text.txt` и вставьте туда текст, который нужно напечатать. Сохраните (кодировка UTF-8).
2. Откройте `config/config.py` в Блокноте (или VS Code) и поменяйте **две строки**:
   ```python
   CURSOR_MODE = "manual"
   TARGET_URL = "https://адрес-вашей-страницы"     # можно оставить пустым и открыть страницу самому
   ```
   Сохраните файл.
3. Запустите: двойной клик по **`run.bat`** (или команда `python app/stealth_typer.py`).
4. Откроется окно Edge. Если нужно — войдите в аккаунт, откройте нужную страницу.
5. **Кликните мышкой в редактор** в то место, где нужно печатать (курсор должен мигать).
6. Вернитесь в чёрное окно и нажмите **Enter**.
7. Скрипт скажет «Начинаю через 3 с…». **Не трогайте мышь и клавиатуру** в окне браузера — печать пойдёт сама.
8. В конце появится `[✓] Текст в поле совпал с исходным на 100%.`
9. Чёрное окно спросит «Нажмите Enter, чтобы закрыть браузер» — нажмите, когда закончите смотреть результат.

Дальше читайте [подробные сценарии](#7-подробные-сценарии-использования), если нужны другие режимы.

## 6. Что лежит в папке проекта

```
Stealth_Typer/
├── run.bat                  ← ЗАПУСК двойным кликом (Windows)
├── start_edge_debug.bat     ← запуск Edge с отладочным портом (для режима "attach")
├── run_my_site.bat          ← шаблон запускалки под один сайт (скопируйте и переименуйте)
│
├── config/
│   └── config/config.py            ← ВСЕ настройки. Это единственный файл, который нужно править
├── texts/
│   ├── input_text.txt       ← текст для ввода по умолчанию (UTF-8)
│   └── page2.html           ← пример второго текста (сюда же кладите свои тексты)
│
├── app/                     ← внутренности программы (обычно сюда заходить не нужно)
│   ├── stealth_typer.py     ← главный файл (запуск, сценарий работы)
│   ├── engine.py            ← «движок печати»: клавиши, скорость, усталость, опечатки
│   ├── browser.py           ← работа с браузером: окно, поиск поля, Monaco, проверка
│   ├── settings.py          ← загрузка и проверка настроек
│   ├── simulator.py         ← имитация редактора для тестов и режима --dry-run
│   ├── run_site_example.py  ← запускалка под сайт на Python (вариант без .bat)
│   ├── requirements.txt     ← список зависимостей (patchright)
│   └── tests/test_engine.py ← автоматические тесты
│
├── data/                    ← создаётся сама: профили Edge, журнал, скриншоты ошибок
├── README.md                ← этот файл
├── LICENSE                  ← лицензия
└── .gitignore               ← что не загружать в Git
```

> README, LICENSE и .gitignore оставлены в корне специально: GitHub показывает README на главной странице репозитория
> и ищет там же лицензию.

Создаются автоматически во время работы:

| Что | Когда | Зачем |
|---|---|---|
| `data/edge_user_data/` | режим `launch` | профиль Edge (куки, вход в аккаунты). Войти нужно один раз |
| `data/edge_debug_profile/` | режим `attach` | отдельный профиль Edge для подключения |
| `data/stealth_typer.log` | всегда (если задан `LOG_FILE`) | журнал работы |
| `data/error_screenshot.png` | при ошибке | снимок страницы в момент сбоя |

> ⚠️ **Папка `data/` (профили `edge_user_data` и `edge_debug_profile`) содержит ваши сессии и куки. Никому их не отдавайте и
> не загружайте в публичный репозиторий.** В `.gitignore` она уже исключена — не удаляйте эти строки.

Менять нужно только **`config/config.py`** и **`texts/input_text.txt`**. Остальные файлы — внутренности.

## 7. Подробные сценарии использования

Во всех сценариях сначала выполнены шаги из раздела [«Установка»](#4-установка-по-шагам-windows).
Запуск — `run.bat` или `python app/stealth_typer.py`.

### Сценарий 1. Новое окно Edge, скрипт сам ставит курсор в Monaco

Подходит, когда вы знаете адрес страницы и номер нужного редактора.

1. В `config/config.py`:
   ```python
   BROWSER_MODE = "launch"
   TARGET_URL = "https://адрес-страницы"
   CURSOR_MODE = "auto"
   FIELD_INDEX = 0          # номер редактора (см. раздел 8, как узнать)
   CURSOR_LINE = "end"      # печатать в самый конец документа
   ```
2. Запустите скрипт. Откроется Edge и загрузит страницу.
3. **Первый раз** войдите в аккаунт прямо в этом окне (если сайт требует вход). Профиль сохранится в `data/edge_user_data/`,
   в следующие запуски входить уже не придётся.
4. Дождитесь, пока страница полностью загрузится и редактор появится на экране.
5. Вернитесь в чёрное окно и нажмите **Enter** на вопрос «Страница готова?».
6. Скрипт найдёт редактор, поставит курсор, подождёт `START_DELAY_S` секунд и начнёт печатать.
7. В конце — проверка результата. Затем Enter — окно браузера закроется.

> Если вход не нужен и страница грузится сама, а вопрос «Страница готова?» мешает, поставьте
> `CONFIRM_BEFORE_START = False` — скрипт не будет спрашивать.

### Сценарий 2. Подключение к уже открытому окну Edge (`attach`)

Подходит, когда вы уже работаете на сайте в обычном окне, вошли в аккаунт, дошли до нужной страницы и хотите,
чтобы скрипт напечатал именно там.

**Почему нельзя подключиться к обычному, уже открытому окну?** Подключение идёт через «отладочный порт» Edge. Он включается
только флагом `--remote-debugging-port` **в момент запуска** браузера; у уже открытого обычного окна его нет, и включить
порт задним числом нельзя. Поэтому Edge нужно запустить через `start_edge_debug.bat` (или дать скрипту сделать это самому).
Сайт при этом можно открыть заранее и в этом же окне — главное, чтобы само окно было запущено с портом.
Удобный вариант: пользуйтесь этим окном как рабочим для нужных сайтов — вход в аккаунты в нём сохраняется между запусками.

**Как это устроено.** Edge нужно запускать со специальным «отладочным портом» — тогда скрипт может подключиться.
Для этого используется **отдельный профиль** (`data/edge_debug_profile`): это окно не мешает вашему обычному Edge,
но и ваших закладок/паролей в нём нет — войти в нужные сайты придётся один раз.
(Насколько мне известно, современные версии Chromium/Edge не открывают отладочный порт для основного профиля,
поэтому отдельный профиль обязателен.)

1. В `config/config.py`:
   ```python
   BROWSER_MODE = "attach"
   ```
2. **Запустите Edge с портом одним из двух способов:**
   - дважды щёлкните **`start_edge_debug.bat`** — откроется окно Edge;
   - **или** оставьте `AUTO_START_EDGE = True` (по умолчанию) — тогда скрипт сам запустит такой Edge, если не найдёт.
3. В этом окне Edge откройте нужный сайт и войдите в аккаунт (один раз, профиль сохранится).
4. Откройте нужную страницу. Можно оставить её открытой и работать с ней как обычно.
5. Запустите скрипт (`run.bat`). Он подключится к окну и напишет `Подключился к вкладке: ...`.
6. Если вкладок несколько, скрипт:
   - возьмёт **ту, что сейчас видна на экране**;
   - если невозможно определить — выведет список и спросит номер вкладки;
   - либо возьмёт вкладку по подсказке `ATTACH_TAB = "часть адреса или заголовка"`.
7. Дальше всё как в сценарии 1 (ответить Enter на «Страница готова?», скрипт печатает, проверяет).
8. **Ваше окно Edge скрипт не закрывает.**

Если в режиме `attach` нужно, чтобы скрипт сам открыл страницу, задайте `TARGET_URL` и `ATTACH_GOTO = True`.

### Сценарий 3. Свой курсор (`manual`)

Подходит, когда редакторов много, структура страницы сложная или вы хотите печатать в произвольное место
(например, в середину документа, между конкретными строками).

1. В `config/config.py`:
   ```python
   CURSOR_MODE = "manual"
   ```
   (`BROWSER_MODE` — как вам нужно: `launch` или `attach`.)
2. Запустите скрипт, подготовьте страницу в браузере (вход, нужная вкладка).
3. **Кликните мышкой в редактор в нужное место.** Курсор должен мигать там, где вы хотите начать.
4. Вернитесь в чёрное окно и нажмите **Enter**.
5. Скрипт сам определит, в каком редакторе стоит курсор, и начнёт печатать именно с этого места.
   Текст, который был в редакторе после курсора, **сохраняется** (он просто сдвигается вниз/вправо).

> Если в редакторе было выделение, скрипт снимет его и напечатает на месте курсора, не удаляя выделенное.
> Хотите заменить фрагмент — удалите его вручную перед запуском.

### Сценарий 4. Обычные поля (`textarea`, `input`, `contenteditable`)

1. Узнайте CSS-селектор поля ([раздел 8](#8-как-найти-нужное-поле-на-странице)).
2. В `config/config.py`:
   ```python
   CURSOR_MODE = "auto"
   FIELD_SELECTOR = "textarea[name='comment']"
   FIELD_INDEX = 0
   CURSOR_LINE = "end"
   ```
   либо `CURSOR_MODE = "manual"` и просто кликните в поле перед Enter.
3. Запустите. Скрипт сам определит тип поля.

Особенности:
- **`input`** (однострочное поле): многострочный текст запрещён — Enter мог бы отправить форму. Скрипт остановится с понятной ошибкой.
- **`contenteditable`** (редакторы вроде Notion-подобных, комментарии): проверка результата нестрогая (сверяется текст без пробелов
  и переносов), потому что такие редакторы по-своему обрабатывают Enter.
- Позицию курсора по номеру строки скрипт умеет ставить только в `textarea`/`input` и Monaco. В `contenteditable` курсор в «auto»
  ставится в конец, для точного места используйте `manual`.

### Сценарий 5. Несколько сайтов

Заведите профили в `config/config.py` (раздел `SITES`, см. [раздел 11](#11-профили-сайтов)) и запускайте так:
```
python app/stealth_typer.py --site my_site
```
Можно подменить файл с текстом: `python app/stealth_typer.py --site my_site --text texts/page2.html`.

## 8. Как найти нужное поле на странице

### Способ 1 (для Monaco): команда `--list`

1. Запустите:
   ```
   python app/stealth_typer.py --list
   ```
   (в режиме `attach` откройте нужную страницу заранее; в режиме `launch` скрипт откроет окно — откройте страницу и нажмите Enter).
2. Скрипт выведет все видимые редакторы **сверху вниз**:
   ```
   Кадр: https://example.com/task — всего редакторов 4, видимых 2
     FIELD_INDEX=0: язык=html, строк=12, размер=640x400, первая строка='<!DOCTYPE html>'
     FIELD_INDEX=1: язык=css, строк=3, размер=640x200, первая строка='body { margin: 0 }'
   ```
3. Запишите нужный номер в `FIELD_INDEX`. Номера считаются **только по видимым** редакторам, скрытые вкладки не учитываются.

Если пишет «Monaco-редакторов не найдено» — на странице либо другой редактор, либо `window.monaco` недоступен. Тогда используйте селектор.

### Способ 2: CSS-селектор через DevTools

1. Откройте страницу в Edge и нажмите **F12**.
2. Вкладка **Elements** → нажмите значок «стрелка в квадрате» (слева вверху панели) → кликните по нужному полю на странице.
3. В подсвеченном HTML найдите `id`, `name`, `class`, `placeholder`, `data-*`.

Примеры селекторов:

| Что нужно | Селектор |
|---|---|
| По `id` | `#message` |
| По `name` | `textarea[name='comment']` |
| По подсказке | `input[placeholder='Введите сообщение']` |
| Редактор в `contenteditable` | `div[contenteditable='true']` |
| Monaco-редактор | `.monaco-editor` |
| По классу родителя | `.chat-input textarea` |

`FIELD_INDEX` в этом случае — номер совпадения (с нуля): если селектор находит 3 элемента, а нужен второй — `FIELD_INDEX = 1`.

> Селектор должен быть **обычным CSS**. Специальные селекторы Playwright (`text=...`, `:has-text(...)`) для Monaco не поддерживаются.

### Способ 3: не искать вовсе

Поставьте `CURSOR_MODE = "manual"`: кликните в нужное поле сами — скрипт найдёт его по положению курсора.

## 9. Подготовка текста

- Текст лежит в файле `TEXT_FILE` (по умолчанию `texts/input_text.txt`), кодировка **UTF-8**.
  В Блокноте: *Файл → Сохранить как → Кодировка: UTF-8*. BOM допускается.
- **Пробелы и табуляции в начале строк сохраняются.** Скрипт ничего не «чистит», кроме пустых строк в самом конце файла
  (это можно отключить: `TRIM_TRAILING_NEWLINES = False`).
- Переводы строк любого вида (`\r\n`, `\n`) приводятся к одному виду, в редакторе используется его собственный перевод строки.
- Файла нет или он пустой → берётся запасной текст `TEXT_INLINE` из `config/config.py`.
- Файл можно выбрать при запуске: `--text texts/page2.html`.
- Управляющие символы (кроме переноса строки и табуляции) удаляются с предупреждением.
- Любые символы допустимы. Те, которых нет на стандартной клавиатуре (`—`, `«»`, `№`, `…`, эмодзи), вводятся как «символ без клавиши»
  (так же, как это делают метод ввода и экранная клавиатура). Если конкретное поле их не принимает — это ограничение сайта.

Сколько займёт ввод (очень приблизительно, для 65 слов в минуту; точнее покажет `--dry-run`):

| Знаков | Время |
|---|---|
| 500 | ≈ 2 мин |
| 2 000 | ≈ 8 мин |
| 5 000 | ≈ 20 мин |
| 10 000 | ≈ 40 мин |

Формула: `знаков ÷ (5 × WPM)` минут, плюс 20–30% на паузы и опечатки. Чем ниже скорость и выше усталость, тем дольше.

## 10. Полный справочник настроек (config.py)

Открывайте `config/config.py` в Блокноте. Строки после `#` — комментарии. Меняйте только значения справа от `=`.
Строки — в кавычках (`"auto"`), числа — без (`60`), `True` / `False` — с большой буквы, без кавычек.

### 10.1. Браузер

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `BROWSER_MODE` | `"launch"` | `"launch"` — открыть **новое** окно Edge. `"attach"` — подключиться к **уже открытому** (нужен отладочный порт, см. сценарий 2) |
| `BROWSER_CHANNEL` | `"msedge"` | Какой браузер запускать в режиме `launch`: `"msedge"` (Edge), `"chrome"` (Google Chrome), `"chromium"` (после `patchright install chromium`) |
| `USER_DATA_DIR` | `"data/edge_user_data"` | Папка профиля для режима `launch` (путь от корня проекта). Там хранится вход в аккаунты |
| `DEBUG_PORT` | `9222` | Порт отладки Edge для режима `attach`. Менять нужно, только если порт занят (тогда поменяйте и в `start_edge_debug.bat`) |
| `AUTO_START_EDGE` | `True` | В режиме `attach`: если Edge с портом не найден — скрипт запустит его сам (профиль `data/edge_debug_profile`) |
| `ATTACH_TAB` | `""` | В режиме `attach`: часть адреса или заголовка нужной вкладки (например `"monaco"`). Пусто — видимая вкладка, а если неясно — спросит номер |
| `ATTACH_GOTO` | `False` | В режиме `attach`: `True` — ещё и перейти на `TARGET_URL` |

### 10.2. Страница и ожидание

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `TARGET_URL` | `""` | Адрес страницы. Пусто — не переходить никуда (откройте страницу сами) |
| `PAGE_LOAD_TIMEOUT_MS` | `30000` | Сколько ждать загрузки страницы, миллисекунды (30000 = 30 секунд) |
| `FIELD_WAIT_TIMEOUT_MS` | `15000` | Сколько ждать появления поля/редактора после «Enter» |
| `CONFIRM_BEFORE_START` | `True` | Спросить «Страница готова? Enter» перед вводом. Нужно для входа в аккаунт и капчи. В режиме `manual` вопрос про курсор задаётся всегда |

### 10.3. Куда ставить курсор

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `CURSOR_MODE` | `"auto"` | `"auto"` — скрипт сам выбирает поле и ставит курсор. `"manual"` — вы кликаете в поле, скрипт печатает с места курсора |
| `FIELD_SELECTOR` | `""` | CSS-селектор поля. Пусто — для Monaco берётся редактор по `FIELD_INDEX` среди видимых |
| `FIELD_INDEX` | `0` | Номер редактора (без селектора) или номер совпадения селектора, с нуля |
| `CURSOR_LINE` | `"end"` | Строка для курсора: `"end"` — последняя, `"start"` — первая, или число (`1`, `2`, `99`...). Если число больше количества строк — берётся последняя |
| `CURSOR_COLUMN` | `"end"` | Колонка: `"end"` — в конец строки, или число (`1` — в самое начало строки) |

Примеры:
- В конец документа: `CURSOR_LINE = "end"`, `CURSOR_COLUMN = "end"`.
- В самое начало: `CURSOR_LINE = "start"`, `CURSOR_COLUMN = 1`.
- В начало 10-й строки: `CURSOR_LINE = 10`, `CURSOR_COLUMN = 1`.

(`CURSOR_LINE` и `CURSOR_COLUMN` действуют только при `CURSOR_MODE = "auto"`.)

### 10.4. Текст

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `TEXT_FILE` | `"texts/input_text.txt"` | Файл с текстом (путь от корня проекта или полный) |
| `TEXT_INLINE` | `""` | Запасной текст, если файла нет или он пустой |
| `TRIM_TRAILING_NEWLINES` | `True` | Убирать пустые строки в самом конце текста |

### 10.5. Скорость и «человечность»

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `WPM_MIN` | `40` | Нижняя граница скорости, слов в минуту (1 слово = 5 знаков) |
| `WPM_MAX` | `90` | Верхняя граница скорости |
| `VARIABILITY` | `0.5` | От 0 до 1. Насколько сильно и часто скорость «гуляет». `0` — почти ровная, `1` — сильно скачет |
| `FATIGUE` | `0.5` | От 0 до 1. Насколько скорость падает от усталости. `0` — усталости нет |
| `FATIGUE_MINUTES` | `6.0` | За сколько минут печати усталость набирается примерно на 63% (за тройное время — на 95%) |
| `PAUSES` | `1.0` | Множитель пауз «подумать». `0` — без пауз, `2` — вдвое больше |
| `INDENT_FAST` | `True` | Отступы в начале строк печатаются быстро (как если зажать пробел или Tab) |
| `TURBO_FROM_WPM` | `150` | С какой скорости включается быстрый режим (см. ниже). `0` — никогда |
| `KEY_HOLD_MS` | `(45, 110)` | Сколько миллисекунд удерживается клавиша: (от, до) |
| `ERROR_RATE` | `0.02` | Вероятность опечатки на каждую букву (0.02 = 2%). `0` — без опечаток. Все опечатки исправляются |
| `SWAP_SHARE` | `0.25` | Какая доля опечаток — «перестановка двух соседних букв» |
| `DOUBLE_SHARE` | `0.15` | Какая доля — «двойное нажатие». Остальное — «соседняя клавиша» (`SWAP + DOUBLE` не больше 1) |
| `TYPO_NOTICE_MAX` | `3` | Через сколько знаков (0…N) человек замечает опечатку и стирает её |
| `START_DELAY_S` | `3` | Пауза перед началом ввода, секунды: успеть убрать руки от мыши |

Готовые наборы значений:

| Стиль | WPM_MIN–MAX | VARIABILITY | FATIGUE | ERROR_RATE | PAUSES |
|---|---|---|---|---|---|
| Медленно, вдумчиво | 30–55 | 0.5 | 0.5 | 0.03 | 1.5 |
| Обычный человек | 40–90 | 0.5 | 0.5 | 0.02 | 1.0 |
| Опытный печатающий | 70–120 | 0.4 | 0.3 | 0.01 | 0.7 |
| Быстро, без «живости» | 100–130 | 0.2 | 0 | 0 | 0 |

#### Как выжать максимальную скорость (для обычного текста)

Быстрый режим включается сам, когда текущая скорость достигает `TURBO_FROM_WPM` (по умолчанию 150 WPM ≈ 750 знаков/мин):
клавиши уходят в браузер пачкой, без ожидания ответа на каждую, без пауз на удержание и на Shift, а время на обмен
с браузером не накапливается (скрипт ориентируется на расписание, а не на «паузу после каждой клавиши»).
При этом клавиши остаются настоящими событиями ввода, а не вставкой.

Настройки для потолка скорости:

```python
WPM_MIN = 1000
WPM_MAX = 1000
VARIABILITY = 0
FATIGUE = 0
PAUSES = 0
ERROR_RATE = 0
```

Потолок упирается уже не в скрипт, а в браузер и сам сайт (обработка каждой клавиши редактором). Если печать начала
терять знаки или отставать — снижайте скорость. Для кода держите `WPM_MAX` ниже `TURBO_FROM_WPM`: тогда включается
обычный «человеческий» режим с проверкой автоотступов и скобок после каждого важного знака.
В быстром режиме на Windows короткие паузы отсчитываются «вращением» цикла, поэтому процессор может грузиться на 100% одного ядра — это нормально.

### 10.6. Monaco и редакторы кода

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `MONACO_MODE` | `"natural"` | Как вести себя с «помощью» редактора. `"natural"` — помощь **оставлена**, скрипт работает вместе с ней: кавычки и скобки печатаются внутри и «проходят» через уже стоящий закрывающий знак; после Enter принимается отступ редактора и подгоняется под ваш текст; если Enter между тегами/скобками создал пустую строку — второй Enter не нажимается, скрипт уходит вниз к закрывающему знаку. `"literal"` — помощь **отключена**, всё печатается буквально (запасной вариант) |
| `MONACO_DISABLE_AUTOFEATURES` | `True` | Отключать на время ввода подсказки, автодополнение и форматирование (они ломают Enter). Рекомендуется всегда `True` |
| `MONACO_RESTORE_OPTIONS` | `True` | После ввода вернуть настройки редактора как были |
| `AUTOCLOSE_MODE` | `"skip"` | Что делать с тем, что редактор/сайт вставил справа от курсора (`</div>`, `)`, `"`). `"skip"` — печатать внутри и перепрыгивать (End / стрелка / проходная печать закрывающего знака). `"delete"` — сразу удалять вставленное клавишей Delete и печатать закрывающие знаки вручную (запасной вариант) |
| `AUTOCLOSE_WAIT_MS` | `300` | Сколько миллисекунд ждать, не вставит ли сайт закрывающий тег после `>`. `0` — не ждать. Если закрывающие теги появляются поздно — увеличьте (например, `600`) |

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `KEEP_BROWSER_OPEN` | `True` | Режим `launch`: после ввода окно остаётся открытым, пока вы не нажмёте Enter в консоли. `False` — закрыть сразу при успехе |
| `VERIFY_RESULT` | `True` | После ввода сверить текст в поле с исходным |
| `SCREENSHOT_ON_ERROR` | `True` | При ошибке сохранить `data/error_screenshot.png` |
| `LOG_FILE` | `"data/stealth_typer.log"` | Файл журнала. Пустая строка `""` — не вести |
| `RANDOM_SEED` | `None` | Число — «почерк» повторяется один в один (для отладки). `None` — каждый раз по-новому |

## 11. Профили сайтов

Профиль — это набор настроек, **отличающихся** от общих, под конкретный сайт. Пример в `config/config.py`:

```python
SITES = {
    "my_site": {
        "BROWSER_MODE": "attach",
        "ATTACH_TAB": "mysite.com",
        "FIELD_INDEX": 1,
        "CURSOR_LINE": "end",
        "WPM_MIN": 50,
        "WPM_MAX": 80,
    },
    "comment_form": {
        "FIELD_SELECTOR": "textarea[name='comment']",
        "TEXT_FILE": "texts/comment.txt",
        "ERROR_RATE": 0.03,
    },
}
```

Правила:
- Ключи — те же названия настроек, что в разделе 10, **заглавными буквами**, в кавычках.
- Названия профилей — любые (можно по-русски), в кавычках.
- Между профилями ставится запятая. После последней запятая допускается.
- Опечатка в названии настройки внутри профиля — скрипт сообщит об этом при запуске.

> ⚠️ **Называйте профили латиницей** (`my_site`, `shop_1`), без пробелов. Русские названия (`мой_сайт`) ломаются, когда скрипт
> запускают из `.bat`-файла или через `os.system(...)`: Windows портит кодировку, и вместо `мой_сайт` скрипт получает «набор непонятных символов»
> (ошибка `Профиль сайта «...» не найден`). Скрипт пытается починить такие имена сам, но надёжно — только латиница.

Как применять:
- Постоянно: в `ACTIVE_SITE = "my_site"`.
- На один запуск: `python app/stealth_typer.py --site my_site` (имеет приоритет над `ACTIVE_SITE`).

Порядок приоритета (от низкого к высокому): общие настройки → профиль сайта → параметры командной строки.

### Свои запускалки под каждый сайт

Чтобы запускать сайт одним двойным кликом, а не набирать команду:

**Вариант 1. `.bat`** — скопируйте `run_my_site.bat`, назовите по сайту (например `run_shop.bat`) и поменяйте одну строку:
```
set SITE=shop_1
```
Внутри используется `run.bat`, поэтому виртуальное окружение подхватывается само. В этом файле **не должно быть русских букв**.

**Вариант 2. `.py`** — скопируйте `app/run_site_example.py`, например в `app/run_shop.py`, и поменяйте `SITE = "shop_1"`.
Запускайте тем же Python, где установлен `patchright` (из `venv`: `venv\Scripts\python app\run_shop.py`).
Скрипт вызывает программу напрямую (`stealth_typer.main([...])`), без командной строки, поэтому кодировка не страдает.

Если всё же запускаете из своего `.py` командой, используйте **список аргументов**, а не `os.system`:
```python
import subprocess, sys
subprocess.run([sys.executable, "app/stealth_typer.py", "--site", "shop_1"])
```
Дополнительные параметры (`--text`, `--wpm` и т.д.) допишите в тот же список.

## 13. Скорость, усталость и паузы: как это устроено

### Скорость

Скорость считается в **словах в минуту** (WPM, 1 слово = 5 знаков): 60 WPM ≈ 5 знаков в секунду.

Каждый запуск у «печатающего» свой **базовый уровень** (кто-то быстрее, кто-то медленнее) внутри диапазона `WPM_MIN … WPM_MAX`.
Текущая скорость плавно тянется к этому уровню, при этом:

- **Случайные колебания** (`VARIABILITY`) двигают скорость вверх-вниз. Постоянной цифры нет.
- **Усталость** (`FATIGUE`, `FATIGUE_MINUTES`) растёт со временем и снижает «целевой» уровень. При `FATIGUE = 1` и долгом вводе
  скорость приближается к `WPM_MIN`.
- **Отдых**: редкие паузы на концах строк частично сбрасывают усталость (человек отдохнул и снова бодр).
- **«Разгоны» и «просадки»**: изредка на 4–12 секунд скорость заметно растёт или падает.
- Время усталости считается **по часам, а не по длине текста**: за 6 минут (по умолчанию) вы устанете одинаково и на 1 000, и на 10 000 знаков.
- Сложные знаки медленнее: заглавные буквы, цифры, знаки препинания — примерно на 25–30%; пробел немного быстрее; Enter — медленнее.
  Отступы в начале строк — в 3 раза быстрее (`INDENT_FAST`).
- У каждого интервала между клавишами есть случайный «шум» ±30%.

### Каждое нажатие

1. Для заглавных и символов вроде `!`, `?`, `<`, `>`: сначала **Shift вниз**, затем клавиша, потом **Shift вверх**.
2. Клавиша **удерживается** `KEY_HOLD_MS` миллисекунд (как у человека), затем отпускается.
3. Для кириллицы клавиши берутся с физических позиций русской раскладки (`й` на месте `q`, и т.д.).

### Опечатки

- Могут быть только на буквах (не в отступах и не на знаках), вероятность — `ERROR_RATE` на букву.
- Три вида: **соседняя клавиша** (вместо `о` нажали `п`), **перестановка** (`рпивет`), **двойное нажатие** (`привеет`).
  Соседи берутся по реальному расположению клавиш для латиницы и кириллицы.
- Человек замечает опечатку не сразу: допечатывает ещё 0…`TYPO_NOTICE_MAX` знаков, делает паузу 0.15–0.55 с,
  стирает Backspace и печатает верно.
- Итоговый текст всегда без ошибок — это проверяется тестами.

### Паузы (масштабируются `PAUSES`)

| Где | Как часто | Сколько |
|---|---|---|
| После слова (пробел) | 12% | 0.1–0.35 с |
| После знака `. , ; : ! ?` | 25% | 0.1–0.4 с |
| После конца строки | 50% | 0.2–0.9 с |
| «Задумался» на конце строки | 6% | 1–3.5 с |
| «Отдохнул» на конце строки | 1.5% | 3–8 с (усталость частично сбрасывается) |

## 14. Как скрипт работает с Monaco

Если вам нужно только запускать скрипт — этот раздел можно пропустить. Он нужен, чтобы понимать, что происходит
и почему иногда что-то идёт не так.

1. **Поиск редактора.** Скрипт обращается к `window.monaco` на странице и получает список редакторов
   (`monaco.editor.getEditors()`). Нужный выбирается по `FIELD_INDEX` (среди видимых, сверху вниз), по CSS-селектору
   или по тому, где стоит курсор (`manual`). Поиск идёт и внутри iframe.
2. **Главный контекст страницы.** Patchright по умолчанию выполняет скрипты в изолированном контексте, где `window.monaco`
   не виден. Поэтому вызовы к Monaco идут с параметром `isolated_context=False`. Всё остальное — в изолированном контексте.
3. **Какая «помощь» остаётся.** Подсказки, автодополнение и форматирование при вводе отключаются всегда (иначе Enter принимал бы подсказку).
   В режиме `MONACO_MODE = "natural"` (по умолчанию) всё остальное — автоотступы, автозакрытие скобок/кавычек/тегов — **остаётся включённым**,
   а скрипт подстраивается под него. В режиме `"literal"` это тоже отключается, и текст печатается буквально. После ввода настройки возвращаются.
4. **Контроль после каждого знака.** Скрипт читает позицию курсора, длину документа и текст справа от курсора, поэтому всегда знает,
   что редактор вставил сам. Дальше — как поступает человек:
   - **Теги.** После `<div>` сайт вставил `</div>` — скрипт печатает внутри, а когда в вашем тексте доходит очередь до `</div>`, **не печатает его**,
     а перепрыгивает через уже стоящий (End, если дальше конец строки, иначе стрелка вправо). Перед прыжком он проверяет, что справа
     действительно нужный тег. Вложенные теги в одной строке, незакрытые теги и «лишние» закрывающие теги обрабатываются.
   - **Скобки и кавычки.** После `(`, `[`, `{`, `"`, `'`, `` ` `` редактор вставил закрывающий знак — скрипт печатает внутри и затем просто **печатает закрывающий знак**:
     редактор сам «проходит» через свой (overtype). Если редактор этого не сделал и получился дубль, лишний знак удаляется.
   - **Enter и отступы.** После Enter редактор ставит свой отступ. Скрипт сравнивает его с отступом в вашем тексте: совпал — ничего не делает;
     редактор поставил больше или другой (например, табуляцию вместо пробелов) — стирает Backspace; меньше — допечатывает недостающее.
   - **Enter между двумя тегами или скобками.** Редактор делает пустую строку с отступом, а закрывающий тег уходит ниже:
     ```
     <div>|</div>        →  Enter  →      <div>
                                              |          ← курсор здесь, сюда печатается содержимое
                                           </div>
     ```
     Когда в вашем тексте содержимое закончилось и дальше идёт перенос строки и `</div>`, скрипт **не нажимает второй Enter**: он уходит вниз
     (стрелка вниз), выравнивает отступ закрывающего тега под ваш текст и становится в его конец (End).
   - **Если исходный текст что-то не закрывает**, лишнее, что вставил редактор, удаляется Delete (перед нужным тегом или в самом конце).
   Если сайт вставляет `</tag>` с задержкой, после `>` скрипт до `AUTOCLOSE_WAIT_MS` ждёт его появления.
5. **Режим `"delete"`** (`AUTOCLOSE_MODE`) — всё, что редактор вставил справа от курсора, сразу удаляется Delete, а закрывающие знаки печатаются руками.
6. **Всё, что было в редакторе после курсора, остаётся нетронутым.**
7. **Финальная проверка.** После ввода весь текст редактора сравнивается с ожидаемым (`текст до курсора + ваш текст + текст после`).
   При расхождении скрипт показывает строку, колонку и фрагмент.

Что «незаметно» для сайта: события клавиш — настоящие (`isTrusted = true`), пасты нет, события идут по одному.
Что сайт теоретически может увидеть: временное изменение настроек редактора и обращение к `window.monaco` из контекста страницы
(скрыть это нельзя).

## 15. Что означают сообщения в консоли

Пример успешного запуска:
```
[i] Режим браузера: launch, курсор: auto, скорость 40–90 WPM, знаков: 259
[i] Открываю https://example.com …

>>> Страница готова (вход выполнен, редактор виден)? Нажмите Enter…
[i] Поле: Monaco-редактор №0
[i] Начинаю через 3 с — не трогайте мышь и клавиатуру в окне браузера.
[i] 18% | ≈61 WPM | осталось ≈1:09
[i] 42% | ≈62 WPM | осталось ≈0:42
[✓] Ввод завершён за 1 мин 6 с. Скорость 53–69 (в среднем 62) WPM, опечаток исправлено: 3.
[✓] Текст в поле совпал с исходным на 100%.
```

| Сообщение | Что значит |
|---|---|
| `[i] ...` | Информация |
| `[✓] ...` | Успех |
| `[!] ...` | Предупреждение или ошибка |
| `[i] Профиль сайта: ...` | Применён профиль из `SITES` |
| `[i] Поле: Monaco-редактор №N` | Редактор найден по номеру |
| `[i] Поле: Monaco (где стоит курсор)` | Режим `manual`: найден редактор с курсором |
| `[i] Подключился к вкладке: ...` | Режим `attach`: вкладка выбрана |
| `[i] N% \| ≈60 WPM \| осталось ...` | Прогресс (раз в 15 секунд): текущая скорость и оценка времени |
| `[!] Редактор изменил текст неожиданно` | Сайт сделал что-то непредвиденное рядом с курсором; смотрите итоговую проверку |
| `[!] Текст в поле ОТЛИЧАЕТСЯ от исходного: ...` | Итог не совпал; показаны строка, колонка и фрагменты |
| `[i] Ваше окно Edge не закрываю.` | Режим `attach`: окно осталось открытым |

Всё это дублируется в `data/stealth_typer.log`.

## 16. Проблемы и решения

| Симптом | Причина | Что делать |
|---|---|---|
| `python не является внутренней или внешней командой` | Python не установлен или не добавлен в PATH | Переустановите Python с галочкой «Add python.exe to PATH» или используйте `py` |
| `Не установлен patchright` | Не выполнен `pip install patchright` | Выполните `pip install patchright` (или `python -m pip install patchright`) |
| `Ошибка настроек: ...` | Опечатка или недопустимое значение в `config/config.py` | Прочитайте сообщение — там написано, какая настройка и что не так |
| `Профиль сайта «...» не найден` (в имени странные символы) | Кириллица в имени испортилась при запуске из `.bat`/`os.system` | Назовите профиль латиницей (`my_site`) в `config/config.py` и в запускалке |
| `Профиль сайта «...» не найден` | Нет такого имени в `SITES` | Проверьте написание, регистр и кавычки |
| Окно Edge не открывается (`launch`) | Edge не найден или повреждён профиль | Проверьте установку Edge; попробуйте `BROWSER_CHANNEL = "chrome"`; удалите папку `data/edge_user_data` (потеряется вход) |
| Ошибки вида `'xxx' не является внутренней или внешней командой` при запуске `.bat` | В `.bat` попала кириллица/неверная кодировка | Используйте `.bat` из этого проекта без изменений или правьте только латиницей |
| `Edge с портом ... не найден` | Режим `attach`, а Edge запущен без порта | Запустите `start_edge_debug.bat` или включите `AUTO_START_EDGE = True` |
| `Порт отладки не открылся` | Edge с тем же профилем уже запущен без порта, или порт занят | Закройте **все** окна Edge из `data/edge_debug_profile`, запустите `start_edge_debug.bat`; при занятом порте смените `DEBUG_PORT` |
| `Вкладка с «...» не найдена` | `ATTACH_TAB` не совпадает ни с адресом, ни с заголовком | Уточните текст или очистите `ATTACH_TAB` |
| `Поле не найдено` | Неверный `FIELD_INDEX`/`FIELD_SELECTOR`, страница ещё не загрузилась | Выполните `--list`; проверьте селектор в DevTools; увеличьте `FIELD_WAIT_TIMEOUT_MS`; дождитесь загрузки перед Enter |
| `Monaco-редактор не найден` | На странице нет Monaco или нет `window.monaco` | Используйте `FIELD_SELECTOR`; или `CURSOR_MODE = "manual"` |
| `Не нашёл поле с курсором` | В режиме `manual` вы не кликнули в поле, или кликнули не в редактор | Кликните в редактор (должен мигать курсор), затем Enter в консоли |
| `Редактор доступен только для чтения` | У редактора включён `readOnly` | Выберите другой редактор (`--list` показывает «только чтение») |
| `Текст многострочный, а поле однострочное` | Выбрано `input` | Выберите `textarea` или редактор |
| Печатается не туда / не в тот редактор | Неправильный номер редактора | `--list`, затем уточните `FIELD_INDEX`; либо используйте `manual` |
| Ничего не печатается, окно не в фокусе | Окно свёрнуто | Не сворачивайте окно браузера; скрипт сам выводит его на передний план |
| После ввода `Текст в поле ОТЛИЧАЕТСЯ` | Сайт вмешался (поздняя автовставка тегов, свои обработчики) | Увеличьте `AUTOCLOSE_WAIT_MS` (например, `600`); посмотрите диагностику «первое расхождение» |
| Закрывающие теги дублируются | Автозакрытие приходит позже, чем ждёт скрипт | `AUTOCLOSE_WAIT_MS = 600` или `1000` |
| Отступы, скобки или кавычки «съезжают» | Редактор на сайте по-своему форматирует код | Попробуйте `MONACO_MODE = "literal"` (помощь редактора отключается) и/или `AUTOCLOSE_MODE = "delete"`; пришлите лог |
| Теги и отступы «съезжают» в режиме по умолчанию | Сайт по-своему форматирует код при Enter или автозакрытии | Попробуйте `AUTOCLOSE_MODE = "delete"` и пришлите лог |
| Страница в окне скрипта светлая, хотя система тёмная; после остановки скрипта снова тёмная | Playwright/Patchright по умолчанию принудительно включают светлую тему | Настройка не нужна: скрипт всегда использует системную тему. Если тема всё равно светлая — пришлите вывод консоли |
| Часть символов не вводится | Поле или сайт не принимает редкие символы | Замените символы в тексте; проверьте, что текст в UTF-8 |
| Скрипт ругается на `maxlength` или текст обрезан | У поля есть ограничение длины | Сократите текст |
| В конце строк нет отступов / отступ лишний | Автоотступ редактора не отключился | Проверьте `MONACO_DISABLE_AUTOFEATURES = True`; сообщите в Issues с логом |
| Вылетает капча / блокировка | Сайт заподозрил автоматизацию | Снизьте скорость (`WPM_MIN/MAX`), увеличьте `PAUSES`, смените профиль (`USER_DATA_DIR`), подождите. Гарантий нет |
| Слишком долго | Низкая скорость и усталость | Повысьте `WPM_MIN/MAX`, уменьшите `FATIGUE`/`PAUSES`; оценку покажет `--dry-run` |
| После Ctrl+C редактор странно себя ведёт | Не успели вернуться настройки Monaco | Обновите страницу (F5) |
| Ошибка и сразу закрылся браузер (`KEEP_BROWSER_OPEN = False`) | Закрытие по настройке | Поставьте `True` — при ошибке окно в любом случае ждёт Enter в режиме `launch` |

**Куда смотреть при любой неполадке:**
1. Последние строки в чёрном окне.
2. `data/stealth_typer.log` — полный журнал с подробностями ошибки.
3. `data/error_screenshot.png` — как выглядела страница в момент сбоя.

Если пишете Issue в репозитории, приложите: версию Python (`python --version`), ваш `config/config.py` (без секретов), `data/stealth_typer.log`.

## 17. Частые вопросы

**Нужно ли открывать Edge вручную?**
В режиме `launch` — нет, скрипт откроет его сам. В режиме `attach` — запустите `start_edge_debug.bat` (или скрипт запустит сам при `AUTO_START_EDGE = True`).

**Можно ли использовать Google Chrome вместо Edge?**
Да, в режиме `launch`: `BROWSER_CHANNEL = "chrome"`. Для `attach` запустите Chrome с `--remote-debugging-port=9222` и отдельным `--user-data-dir`.

**Работает ли на macOS и Linux?**
Код кроссплатформенный, но проект разрабатывался и проверялся под Windows. `start_edge_debug.bat` — только для Windows; на macOS/Linux запустите Edge вручную:
```
"/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge" --remote-debugging-port=9222 --user-data-dir="$HOME/edge_debug"
```
(или `AUTO_START_EDGE = True`, скрипт попробует сам). Для `launch` может понадобиться `BROWSER_CHANNEL = "chrome"` или `"chromium"`.

**Можно ли запустить без окна (headless)?**
Нет, и это сделано намеренно: безголовый режим легче распознаётся сайтами.

**Можно ли печатать в iframe?**
Monaco ищется во всех кадрах страницы, обычные поля — тоже.

**Сколько времени займёт мой текст?**
Смотрите таблицу в [разделе 9](#9-подготовка-текста) или запустите `--dry-run`.

**Могу ли я работать за компьютером, пока скрипт печатает?**
Да, но **не трогайте мышь и клавиатуру в окне браузера**, не сворачивайте его и не переключайте вкладку. В других окнах — можно.

**Как напечатать в конкретное место, а не в конец?**
`CURSOR_MODE = "manual"` и кликните в нужное место, либо `CURSOR_LINE`/`CURSOR_COLUMN` в режиме `auto`.

**Как стереть то, что было в редакторе?**
Скрипт ничего не стирает. Очистите редактор вручную перед запуском (в Monaco: Ctrl+A, Delete).

**Нужны ли мне права администратора?**
Нет.

**Нужно ли вводить пароль или входить в аккаунт?**
Только если сайт этого требует. Делается вручную в окне браузера — один раз; сессия сохраняется в профиле.

**Безопасно ли это? Что скрипт отправляет в интернет?**
Скрипт ничего не отправляет на сторонние серверы: он управляет браузером на вашем компьютере. Единственный сетевой трафик — открытие вами выбранных сайтов.
Профили браузера (папка `data/`) содержат ваши куки — храните их приватно.

**Как удалить всё?**
Удалите папку проекта и, при желании, `pip uninstall patchright`.

## 18. Проверка без браузера и тесты

### Dry-run

```
python app/stealth_typer.py --dry-run
python app/stealth_typer.py --dry-run --wpm 60-100 --text texts/page2.html
```
Скрипт «печатает» текст в встроенный симулятор редактора (с автозакрытием тегов, скобок и автоотступом), не открывая браузер.
Выводит ожидаемое время, диапазон скорости, число опечаток и сообщает, совпал ли результат с исходным.
Удобно, чтобы заранее прикинуть время и подобрать скорость.

### Автоматические тесты

```
python -m unittest discover -s app/tests -v
```
Проверяют (на симуляторе): раскладку клавиш и все символы, границы скорости и влияние усталости, исправление опечаток,
сохранение отступов и кириллицы, работу при автозакрытии тегов (в том числе с задержкой), сохранение текста после курсора,
обнаружение «слишком позднего» автозакрытия, работу с `\r\n`, проверку настроек.

> Тесты проверяют логику, но не реальный сайт и не реальный браузер. Поведение конкретного сайта лучше проверить
> первым запуском на тестовом тексте.

Хорошая «песочница» для первого запуска — официальная страница-пример Monaco Editor (Monaco Playground).

## 19. Ограничения и честные ожидания

- **Стопроцентной невидимости не бывает.** Скрипт имитирует ввод с клавиатуры: ритм, удержание клавиш, Shift, опечатки,
  паузы. Но сайт может анализировать другое: движение мыши, скролл, поведение страницы, собственные метрики, отпечатки браузера.
  Мышь в текущей версии не эмулируется.
- **Капча и блокировки возможны** даже при идеальном вводе (частые запуски, подозрительный аккаунт, IP).
- **Работа зависит от сайта.** Редактор, который сильно переопределяет поведение Monaco, может потребовать подстройки
  (`AUTOCLOSE_WAIT_MS`, выбор редактора и т.п.).
- **Закрытые Shadow DOM, CodeMirror, Ace и прочие редакторы** обрабатываются как обычные поля, а результат проверяется нестрого.
- **Проект проверялся на симуляторе и тестовых сценариях.** Работа на каждом конкретном сайте не гарантируется — при проблемах
  создайте Issue с логом.
- **Режим `attach`** требует отдельного профиля Edge и запуска с отладочным портом.
- **Длительный ввод** зависит от скорости: тысячи знаков занимают десятки минут. Это нормально.
