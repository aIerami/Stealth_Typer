# Stealth Typer

Скрытный посимвольный ввод текста в браузере Microsoft Edge.
Эмуляция человеческой печати через [Patchright](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright) + [HumanTyping](https://github.com/regelstrecke/humantyping).
**Без вставки из буфера обмена** — только эмуляция нажатий клавиш (`keydown → keypress → input → keyup` для каждого символа).

## Зачем это нужно

На некоторых сайтах стоит защита от автоматизации, включая **детекцию вставки из буфера обмена** (paste detection). Стандартные методы Playwright (`page.fill()`, `page.insert_text()`, `execCommand('insertText')`) устанавливают значение поля напрямую через CDP — это видно детекторам по отсутствию клавиатурных событий и единственному `input`-событию с полной строкой.

Этот проект решает задачу иначе: имитирует именно **посимвольную человеческую печать** с:
- неравномерным ритмом (Markov chain в HumanTyping);
- случайными паузами на пунктуации;
- опечатками (соседние клавиши по раскладке, перестановки букв);
- автоматическим исправлением опечаток по ходу ввода (Backspace/стрелки).

Итоговый текст в поле — идеальный. Процесс — как у живого человека.

## Возможности

- ✅ Посимвольный ввод (`keyboard.press`), без `fill`/`insert_text`/`paste`
- ✅ Настраиваемый диапазон скорости (WPM мин–макс, случайный выбор на запуск)
- ✅ Настраиваемая вероятность опечаток и перестановок (исправляются автоматически)
- ✅ Сохраняемый профиль браузера (`edge_user_data/`) — логин один раз, дальше автоматически
- ✅ Ручной вход при первом запуске (`WAIT_FOR_MANUAL_LOGIN`)
- ✅ Скриншоты при ошибках (`error_page.png`, `error_field.png`, `error_typing.png`)
- ✅ Весь конфиг в одном файле `config.py`

## ⚠️ Важные предупреждения

1. **Юридическое.** Проект предназначен для автоматизации задач, где у вас есть право на такое взаимодействие с сайтом (личный аккаунт, разрешённые сценарии, тестирование собственных сервисов). Использование для спама, обхода санкций, нарушения ToS сайта или чужих аккаунтов — на вашей ответственности. Автор не несёт ответственности за блокировки и последствия.
2. **100% невидимости не существует.** Связка Patchright + HumanTyping — одна из лучших открытых, но сайт может анализировать TLS/JA3-отпечатки, ML-биометрию, поведение мыши, мета-детекцию stealth-патчей. Капча может появиться даже при идеальном вводе.
3. **Не заменяйте `HumanTyping` на `pyautogui.typewrite()`.** Тот метод слишком однороден и легко детектируется. HumanTyping внутри использует посимвольные `keyboard.press`-события, что критично.
4. **Не используйте `playwright-stealth`** — он устарел и может создать новые утечки поверх уже пропатченного Patchright. Patchright включает нужные патчи сам.
5. **`headless=True` не поддерживается** — headless легче детектируется. Запуск только с интерфейсом.

## Требования

| Компонент | Версия / условие |
|---|---|
| ОС | Windows (проект разработан и тестирован на Windows 10/11) |
| Python | 3.10 или новее (требование HumanTyping) |
| Microsoft Edge | Установлен в системе (стандартный путь) |


> На macOS/Linux проект, вероятно, тоже заработает, но не тестировался. Понадобится установить Edge или заменить `BROWSER_CHANNEL` на `"chrome"` / `"chromium"`.

## Установка

### 1. Клонировать репозиторий

```bash
git clone https://github.com/<ваш-username>/stealth-typer.git
cd stealth-typer
```

### 2. Создать виртуальное окружение

**PowerShell:**
```powershell
python -m venv stealth-env
.\stealth-env\Scripts\Activate.ps1
```

Если PowerShell жалуется на политику выполнения — один раз выполните:
```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

**cmd:**
```cmd
python -m venv stealth-env
stealth-env\Scripts\activate.bat
```

После активации в начале строки терминала появится `(stealth-env)`.

### 3. Установить зависимости

```bash
pip install --upgrade pip
pip install patchright humantyping[playwright]
```

### 4. Опционально: Chromium как fallback

Если Edge не подхватится по каким-то причинам:

```bash
patchright install chromium
```

И в `config.py` сменить `BROWSER_CHANNEL = "msedge"` на `"chromium"`.

## Настройка

### `config.py` — полный справочник

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `BROWSER_CHANNEL` | Канал Edge/Chrome. `"msedge"` требует установленного Edge. | `"msedge"` |
| `USER_DATA_DIR` | Папка профиля. Куки сохраняются между запусками. | `"./edge_user_data"` |
| `HEADLESS` | Headless-режим. **Не включайте** — детектируется. | `False` |
| `NO_VIEWPORT` | Без фиксированного viewport. Рекомендуется Patchright. | `True` |
| `BROWSER_ARGS` | Доп. аргументы запуска. **Оставьте пустым.** Patchright сам управляет флагами. | `[]` |
| `TARGET_URL` | URL страницы для ввода. | `"https://example.com"` |
| `FIELD_SELECTOR` | CSS-селектор поля. См. раздел «Как найти селектор». | `"#my-text-field"` |
| `WAIT_FOR_MANUAL_LOGIN` | Пауза для ручного входа. `True` — при первом запуске. | `False` |
| `PAGE_LOAD_TIMEOUT_MS` | Таймаут загрузки страницы (мс). | `30000` |
| `TEXT_FILE` | Файл с текстом (UTF-8). | `"input_text.txt"` |
| `TEXT_INLINE` | Резервный текст, если файла нет. | Пример-плейсхолдер |
| `LAYOUT` | Раскладка для «соседних» опечаток. `"qwerty"` / `"dvorak"`. | `"qwerty"` |
| `WPM_MIN`, `WPM_MAX` | Диапазон скорости (слов/мин). Случайный выбор на каждый запуск. | `40`, `90` |
| `ERROR_RATE` | Вероятность опечатки на символ. Итог исправляется. | `0.04` (4%) |
| `SWAP_ERROR_RATE` | Вероятность перестановки соседних букв. | `0.015` (1.5%) |
| `CLOSE_BROWSER_AFTER` | Закрыть браузер после ввода. `False` — оставить открытым. | `True` |

**Ориентиры WPM:**
- `40` — медленно, вдумчиво
- `70` — средний человеческий темп
- `100+` — опытный пользователь

Диапазон `40–90` выглядит естественно для большинства сценариев. Если сайт «параноидальный» — снижайте нижнюю границу.

### `input_text.txt`

- Кодировка: **UTF-8**. В Блокноте: «Сохранить как» → «Кодировка: UTF-8».
- Многострочный текст поддерживается: переносы вводятся как `Enter` (работает в `textarea` и `contenteditable`).
- Скрипт обрезает пробелы по краям (`.strip()`).
- Если файла нет или он пуст — используется `TEXT_INLINE` из конфига.
- Проблемные символы: смайлики и редкие Unicode-символы могут не приниматься полем. Очень длинные строки без пробелов замедляют ввод, но HumanTyping справится.

### Как найти `FIELD_SELECTOR`

1. Откройте целевую страницу в Edge.
2. Нажмите `F12` → вкладка **Elements**.
3. Нажмите на иконку стрелочки в левом верхнем углу панели.
4. Кликните по полю ввода на странице.
5. В подсвеченном HTML найдите `id`, `name`, `placeholder` или `data-*`.

Примеры селекторов:
- `#message` — по `id`
- `textarea[name='comment']` — по `name`
- `div[contenteditable='true']` — для rich-редакторов
- `input[placeholder='Введите сообщение']` — по placeholder
- `.chat-input textarea` — по классу-родителю

> **Если поле внутри iframe** — текущая версия проекта не поддерживает. Потребуется доработка через `page.frame_locator()`.

## Первый запуск (с логином)

Требуется, если сайт требует авторизации.

1. В `config.py` установите:
   ```python
   WAIT_FOR_MANUAL_LOGIN = True
   ```

2. Запустите:
   ```bash
   python stealth_typer.py
   ```

3. Откроется окно Edge, скрипт перейдёт на `TARGET_URL`.

4. **Войдите вручную** в аккаунт в открытом окне (ввод логина/пароля/капчи — всё вручную).

5. Вернитесь в терминал и нажмите **Enter**.

6. Скрипт найдёт поле, кликнет, начнёт печатать.

7. После сообщения `[✓] Ввод завершён` — дождитесь закрытия браузера (или закройте сами).

8. Убедитесь, что появилась папка `edge_user_data/` — там сохранены куки и сессия.

9. В `config.py` выставьте:
   ```python
   WAIT_FOR_MANUAL_LOGIN = False
   ```

При следующих запусках логин уже будет сохранён — скрипт сразу перейдёт к вводу.

## Обычный запуск

```bash
python stealth_typer.py
```

Последовательность:
1. Выбирается случайная скорость WPM из диапазона.
2. Запускается Edge с профилем из `USER_DATA_DIR`.
3. Переход на `TARGET_URL` (таймаут `PAGE_LOAD_TIMEOUT_MS`).
4. Поиск `FIELD_SELECTOR`, клик по нему.
5. Посимвольный ввод с опечатками и их исправлением.
6. Закрытие браузера (если `CLOSE_BROWSER_AFTER = True`).

## Что означает вывод в терминале

При успехе:
```
[i] Целевая скорость: 67 WPM
[i] Переход на https://...
[i] Ищу поле: #message
[i] Клик по полю выполнен. Начинаю посимвольный ввод…
[✓] Ввод завершён. Итоговый текст должен быть без ошибок.
[i] Закрываю браузер…
```

При ошибке — сообщение `[!] ...` и скриншот `error_*.png` в папке проекта:
- `error_page.png` — не удалось загрузить страницу
- `error_field.png` — поле не найдено
- `error_typing.png` — сбой во время ввода

## Проверка, что ввод не похож на вставку

Чтобы убедиться, что детекторы вставки не сработают:

1. Откройте целевую страницу в Edge (можно вручную, вне скрипта).
2. `F12` → вкладка **Console**.
3. Выполните (заменив селектор на свой):
   ```javascript
   const el = document.querySelector('#my-text-field');
   ['keydown','keypress','input','keyup'].forEach(ev =>
     el.addEventListener(ev, e => console.log(ev, e.key))
   );
   ```
4. Запустите скрипт.
5. В консоли должно быть **много отдельных `keydown`** (по одному на символ), а не одно `input` с полной строкой. Это ключевой признак посимвольного ввода.

> `isTrusted` у синтезированных событий будет `false` — это нормально для любой автоматизации. Главное — паттерн посимвольного ввода, а не флаг.

## Остановка

- **`Ctrl+C`** в терминале — корректное завершение, профиль `edge_user_data/` сохранится.
- **Закрытие окна браузера вручную** — скрипт может выдать ошибку, но профиль обычно остаётся целым.
- **Не удаляйте** `edge_user_data/` во время работы.

## Типичные ошибки и решения

| Симптом | Причина | Что делать |
|---|---|---|
| `TimeoutError` при `goto` | Страница не загрузилась за `PAGE_LOAD_TIMEOUT_MS`, сетевые проблемы, неверный URL | Проверить URL вручную; увеличить `PAGE_LOAD_TIMEOUT_MS` до `60000` |
| «Поле не найдено» | Неверный `FIELD_SELECTOR`, поле в iframe, появилось позже | Перепроверить селектор через DevTools; для iframe — нужна доработка |
| «Ничего не печатается» | Поле не получило фокус, `HumanTyping` упал | Открыть `error_typing.png`; проверить, что поле кликается вручную |
| «Печатается не туда» | Селектор совпал со скрытым/другим элементом | Уточнить селектор, добавить `:visible` или более специфичный атрибут |
| Скрипт падает на старте | Не активирован `stealth-env`, не установлены зависимости | Активировать окружение (`(stealth-env)` в начале строки), выполнить `pip install …` |
| «Edge не найден» | Edge не установлен или в нестандартном пути | Установить Edge; либо `BROWSER_CHANNEL = "chromium"` после `patchright install chromium` |
| Капча / блокировка | Сайт распознал автоматизацию или превышен лимит | Снизить `WPM_MIN` до 30–40; сменить `USER_DATA_DIR`; подождать сутки |
| Текст обрезался | Поле имеет `maxlength` или не принимает переносы | Проверить лимит поля; сократить текст |
| Браузер не закрывается | `CLOSE_BROWSER_AFTER = False` или ошибка до `finally` | Выставить `True`; проверить сообщения об ошибках |

## Ограничения и честные ожидания

Связка **Patchright + HumanTyping** — одна из лучших открытых. Patchright убирает утечки CDP, HumanTyping делает ввод неотличимым от человеческого по таймингам и паттерну клавиатуры. **Но:**

- **TLS/JA3-отпечаток** браузера автоматизация не меняет — если сайт проверяет его, он совпадает с обычным Edge, что, впрочем, скорее плюс.
- **ML-биометрия** (движение мыши, скроллинг, время между действиями) — не эмулируется этим проектом. Если сайт анализирует мышь — потребуются дополнительные инструменты.
- **Капча** может появиться при подозрительной активности (частые запуски, много ввода подряд). Решения: снижать скорость, менять профиль, делать паузы между запусками.
- **Поведенческие детекторы** (анализ таймингов нажатий) — HumanTyping работает на Markov chain, но если сайт использует собственную ML-модель, теоретически может распознать.
- **Если сайт блокирует** — никакая библиотека не даст 100% гарантии. Честно: это инструмент снижения риска, а не «серебряная пуля».
